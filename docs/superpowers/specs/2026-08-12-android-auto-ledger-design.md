# 安卓自动记账 App — 设计规格

**日期：** 2026-08-12  
**项目目录：** `记账/`  
**状态：** 已通过头脑风暴确认  

## 1. 目标与成功标准

做一个可下载安装的安卓记账产品：用户付款时自动感知，弹出居中确认卡片，选择消费类型后入账；支持多用户注册登录与云同步。

**第一版验收标准：**

- 微信 / 支付宝付款后能弹出确认卡并完成入账（银行 App 通知尽量覆盖）
- 预置分类可增删改；账本可查、可简单统计、可导出 Excel/CSV
- 注册登录后换机可拉回流水
- 他人可通过下载链接安装 APK 并完成上述流程

## 2. 范围

### 2.1 包含（第一版）

- Android 原生客户端（Kotlin）
- FastAPI 后端：注册/登录、分类与流水云同步、导出所需数据接口
- 通知监听自动捕获付款 → 居中卡片强制确认入账
- 本地 Room 优先，联网后同步
- 签名 APK + 简单下载页或 GitHub Releases

### 2.2 不包含（第一版）

- iOS
- 应用商店上架
- 家庭共享同一账本 / 实时协作
- 复杂预算、多币种、投资账户
- 读取支付 App 内部加密账单（仅通知；短信为可选增强）

## 3. 用户与核心场景

- **角色：** 多用户，各自独立账号与账本
- **主场景：** 付款成功 → 系统通知被监听 → 居中确认卡 → 下拉选择消费类型（必选）→ 可选备注 → 确认入账 → 本地保存并异步同步
- **约束：** 检测到付款后**必须入账**，不提供「忽略」；若当时无法操作，进入本机「待确认」队列，直到确认完成

## 4. 架构

```
Android App (Kotlin)
  通知监听服务 → 付款解析器 → 居中确认弹窗
                              ↓
                         本地 Room DB ←→ 账本 / 统计 / 分类 / 导出 UI
                              ↓ HTTPS
FastAPI 后端
  注册登录(JWT) · 流水同步 · 分类同步 · 导出数据
  存储：第一版 SQLite，可迁移 PostgreSQL
                              ↓
APK 分发：下载页 / GitHub Releases
```

**技术选型依据：** 通知监听必须贴近 Android 系统能力，故客户端原生 Kotlin；后端用 FastAPI 以匹配既有 Python 经验，并支撑多用户产品化。

## 5. 客户端功能设计

### 5.1 付款捕获

- 使用 `NotificationListenerService` 监听微信、支付宝、常见银行 / 云闪付等通知
- 解析字段：金额、商户（或摘要）、来源、时间
- 去重键：来源 + 金额 + 时间窗（及通知特征），避免重复入账
- 可选（默认关闭）：读取银行短信作为补充；不阻塞主路径

### 5.2 确认弹窗（外观与交互已定稿）

- **形态：** 居中卡片，压暗背后界面（需悬浮窗 / 全屏 Intent 等权限）
- **展示：** 来源标识、金额（大号）、商户、消费类型下拉、备注（可选）
- **唯一主操作：** 「确认入账」（无「忽略」）
- **视觉方向：** 纸感浅底、青绿主按钮、清晰层级（头脑风暴稿 `popup-look-v3`）
- **解析失败：** 仍弹窗，金额 / 商户允许手改后再入账
- **弹窗被系统拦截：** 状态栏持续「待入账」通知，点击进入同一确认页

### 5.3 分类

- 预置：餐饮、交通、购物、住房、娱乐、医疗、教育、其他
- 用户可在设置中增删改、排序
- 确认入账前必须选择分类

### 5.4 账本 UI（第一版）

- 流水列表（按日分组）
- 简单统计（按日 / 月支出汇总、按分类占比即可）
- 分类管理
- 手动补记（含收入，作为补充入口）
- 导出 Excel/CSV
- 引导页：逐步开启通知使用权、悬浮窗、电池白名单等

### 5.5 本地数据与待确认

- Room 表：用户会话缓存、分类、流水、待确认付款、同步元数据
- `PendingPayment` 仅存本机；确认后写入 `Transaction` 并标记待同步

## 6. 后端与同步

### 6.1 实体

| 实体 | 说明 |
|------|------|
| User | 邮箱或手机 + 密码；JWT |
| Category | 预置种子 + 用户自定义 |
| Transaction | 金额、商户、来源、分类、备注、发生时间、客户端幂等 ID |
| SyncCursor | 每用户增量同步游标 |

### 6.2 同步规则

- **本地优先：** 确认入账先写 Room，再 `pending_sync` 上传
- **增量：** 上传未同步变更；拉取服务端自游标以来的增量
- **冲突：** 个人账本冲突极少，以最后修改时间为准
- **幂等：** 客户端生成稳定 ID，服务端去重
- **未登录：** 允许本地强制入账；登录后批量上传

### 6.3 API 能力（逻辑分组）

- 认证：注册、登录、刷新令牌
- 分类：列表、创建、更新、删除、同步
- 流水：同步推送 / 拉取、按条件查询（供统计与导出）

## 7. 权限与异常

**必开：** 通知使用权、悬浮窗（或等价展示能力）、后台 / 电池白名单、网络。  
**可选：** 短信。

**已知限制：**

- 依赖各 App 通知文案，对方改版需更新解析规则
- 部分国产机需用户手动锁定后台
- 无法直接读取支付 App 内部流水

## 8. 分发与隐私

- 签名 APK；下载页或 GitHub Releases 提供安装包与版本说明
- 下载页写明：允许未知来源、权限清单、隐私说明（仅处理支付相关通知文本用于记账，不出售数据）
- 第一版不上应用商店；可后续加应用内检查更新

## 10. 测试要点（第一版）

- 真机：微信 / 支付宝实付或可复现的付款通知，验证弹窗与入账
- 去重：短时间重复通知不产生两笔
- 离线入账后恢复网络能同步
- 登录换机（或清数据重装）后流水可拉回
- 未授权通知监听时，引导页能阻断并指引开启
